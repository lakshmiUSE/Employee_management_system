## Project: Employee Management System

#### About the Project

The Employee Management System is designed for candidates who are new to Python and want to gain hands-on experience with fundamental programming concepts.

Through this project, learners will develop practical skills in Python by building an application to manage employee information, including adding, viewing, updating, and deleting employee records.

The project covers the following key Python concepts:

**Data Types and Variables:** Store and manage employee information.
**Conditional Statements:** Implement decision-making logic for employee operations.
**Loops:** Iterate through employee records and display information.
**File Operations:** Store and retrieve employee data using files.
**Error Handling:** Handle invalid inputs, missing files, and unexpected errors.
**Modularization:** Organize code into separate modules for better readability and maintainability.
**Object-Oriented Programming (OOP):** Use classes and objects to represent employees and manage employee-related operations.

#### Project Objective

The primary objective of this project is to help beginners understand and apply core Python programming concepts by developing a practical, real-world application.
By completing this project, learners will gain confidence in writing structured, reusable, and maintainable Python code.

#### Submission Guidelines
`Feature Branch:` Create the feature branch using the naming convention feature_name/dev_enrollmentId.

`Pull Request (PR) Title:` Follow the format IssueId | TaskId : Summary of the Issue | Task.

`Commit Message:` Ensure the commit message clearly summarizes the changes made.

Unit Test Coverage: Achieve more than 80% code coverage through unit tests.


#### Git Commit Standards

Follow this commit message format:

<type>: <short description>

Allowed Types:

`src` — Source code changes.

Example: src: add employee management functionality

`doc` — Documentation changes.

Example: doc: update README setup instructions

`config` — Configuration changes.

Example: config: add Pipenv configuration

##### Guidelines:

Use only src, doc, or config as commit types.
Keep commit messages clear and concise.
Use the imperative mood (e.g., add, update, fix).
Ensure each commit represents a logical change.
